# 死之弓:实现与依据

## 结论

- 武器为单实例 + 内部状态:模式(普通/闪弓)、蓄力阶(1~4)、剩余次数(0~4)全部保存在武器组件里,不生成第二件物品,也不替换贴图。
- 远程射击走**武器自身的射击动词**,因此命中率、掩体、天气、射手精度、战斗日志、鼠标悬停命中率提示全部是原版链路;蓄力阶的精度加成通过武器精度统计叠加,命中判定直接读取。
- 次数与弹药:闪弓每射一次消耗 1 次,次数由"死之箭"从背包装填补满;次数为 0 时无法远程射击,需手动切回普通模式,只保留近战。

## 手持四向贴图：已部署用例（2026-09-26）

**结论**：游戏目录中的武器 XML 已设为 `Graphic_Multi`，且 `Textures/Weapon` 已有 `Bow_of_Death_south.png`、`Bow_of_Death_east.png`。实测仍只显示单张图，原因是原版手持装备绘制固定取 `eq.Graphic.MatSingleFor(eq)`；普通 `Graphic_Multi` 的 `MatSingleFor` 返回 `MatSingle`，即南向材质。死之弓 C# 没有接管武器本体的材质选择或四向偏移。

- 已部署贴图：基础 `Bow_of_Death.png` 与 `_south.png` 的 SHA-256 完全相同；`_east.png` 是另一张图；没有 `_north.png`、`_west.png`。`Graphic_Multi.Init` 读取四向后缀；缺北向时复用南向，缺西向时复用东向并按 `allowFlip` 决定翻转。这个缺图回退规则与手持固定取南向是两个独立环节。
- 已部署的 `Defs/ThingDefs_Items/Weapon_BowOfDeath.xml` 与工作区 XML 不同：游戏目录为 `Graphic_Multi`，工作区仍是 `Graphic_Single`。两处死之弓 `Thing_DeathBow.cs`、`CompEquippable_DeathBow.cs` 和 `Assemblies/ClassLibrary1.dll` 的 SHA-256 各自相同，因此当前差异集中在已部署的 XML 与贴图，不在这两份 C# 或主程序集。
- 手持位置在原版链路中由 `DrawEquipmentAndApparelExtras` 按瞄准角及 `0.4 + def.equippedDistanceOffset` 计算；角度由 `DrawEquipmentAiming` 按瞄准角及 XML 的 `equippedAngleOffset=220` 计算。`graphicData.drawOffset` 与四向 `drawOffsetNorth/East/South/West` 不进入手持绘制方法；`uiIconPath` 只控制 UI 图标。要让手持外观按方向换图，需要使实际绘制路径按朝向选材质，单改 `Graphic_Multi` 与方向图无法实现。
- `Mote_DeathBowAimStreakVfx.WeaponDrawDistance=-1f` 是四阶蓄力流线 Mote 的独立位移常量，不决定武器本体位置；当前值也不等于原版装备前移基数 `0.4f`。

## SYS 四向手持接口边界（工作区 Ratkin 1.6）

**结论**：`Weapon_Box.xml` 的父定义是原版 `BaseMeleeWeapon_Sharp_Quality`，SYS 由显式添加的组件接入。SYS 有四向参数，但没有能直接调整死之弓当前主图「瞄准时」位置的 XML 接口：`CompProperties_WeaponExtention` 的四向 `position/angle` 仅用于非瞄准持握；`CompProperties_Sheath` 的四向参数仅控制另画的一层图。

- SYS 对 `PawnRenderUtility.DrawEquipmentAndApparelExtras` 的前缀补丁会替代原版方法。非瞄准且公开持武器时，存在 `CompWeaponExtention` 才读取 `north/east/south/westOffset.position` 并直接加到绘制位置，使用相应 `angle`；南/西另传 `isFlip=true`。该分支的 SYS `DrawEquipmentAiming` 固定取 `eq.Graphic.MatSingle`，用固定 `MeshPool.plane10`，不读取 `graphicData.drawSize` 或 `ThingDef.equippedAngleOffset`。
- 瞄准分支不读取四向 `position/angle`，而调用原版 `PawnRenderUtility.DrawEquipmentAiming`；`littleDown` 只额外修改 z。故这些 XML 四向数值仅能调整非瞄准持握，不能调整瞄准中的四向姿态或距离。
- `SYS.CompProperties_Sheath` 的 `sheathOnlyGraphicData` 在瞄准与公开持武器时都会绘制，`fullGraphicData` 在收起武器时绘制；其 `DrawSheath` 用 `graphic.MatAt(pawn.Rotation)` 选四向图，并按 `drawPosition` 与四向 `position/angle` 画出独立图层。派送箱将手持时的 `sheathOnlyGraphicData` 设为空图，背负时的 `fullGraphicData` 设为 `Graphic_Multi`；其形态手持主图由 `WeaponMode.GetGraphic` 固定构造为 `Graphic_Single`。
- 条件性复用途径：只有把死之弓的可见手持图改由 `CompProperties_Sheath.sheathOnlyGraphicData=Graphic_Multi` 承载，才可用该组件的四向 XYZ/角度调图。此时必须另行隐藏原有主武器绘制，否则画出两把弓；用 XML 永久改为透明主图又会使落地图不可见，所以仍需 `Thing_DeathBow.Graphic` 按装备状态切换。`fullGraphicData` 可设透明图维持未持武器时隐藏，既有 `uiIconPath` 可维持 UI 图标。Ratkin 的 `RK_Texture_Empty.png` 是 128×128、全部 alpha=0 的透明图。这是更换绘制图层的方案，不是现有主图的直接 XML 调参。
- 仅添加 `CompProperties_WeaponExtention` 可以复用非瞄准四向位置与角度，却仍只画单张手持材质，且会改变目前非瞄准持握的尺寸/角度链路。仅覆写 `MatSingleFor` 的自定义图形类也无法影响 SYS 非瞄准分支，因为它直接调用 `MatSingle`。若采用前述鞘层复用方案，不必添加 `CompProperties_WeaponExtention`。

**证据**：`鼠鼠收尾人们目前已到245679协会/Defs/ThingDefs_Items/Weapon_Box.xml:3,281-326`；`Source/ClassLibrary1/Weapon/Weapon_DeliveryBox.cs:74-81,435-453`；工作区 `Ratkin/1.6/Assemblies/SYS.dll` 定向反编译 `SYS.CompProperties_WeaponExtention`、`SYS.Offset`、`SYS.DrawEquipment_WeaponBackPatch.DrawEquipmentAndApparelExtrasPrifix/DrawEquipmentAiming/DrawSheath`、`SYS.CompProperties_Sheath`。

## 东西向瞄准偏移（工作区实现）

`WeaponExtention` 属于 SYS 而非原版；其四向偏移不进入瞄准分支。死之弓由 `DeathBowAimDrawOffsetPatch` 在原版 `DrawEquipmentAiming` 入口读取本武器 XML 的 `aimDrawOffsetEast/West`，按瞄准角选择东/西并叠加世界坐标偏移。当前东、西均为 `(0,0,0.2)`；北、南和其他武器不变。SYS 的非瞄准四向持握直接调用自身绘制方法，不进入该原版入口。已通过工作区 Release 编译与 XML 解析，尚未在游戏中验收。

## 非瞄准持握偏移（工作区实现）

原版非瞄准持握使用固定四向基准，没有四向独立的 XML 偏移；死之弓用 SYS `CompProperties_WeaponExtention` 提供四向 `position/angle`。北保留 SYS 原基准 `(0,-0.3,-0.11)`；南由 `(0,0.3,-0.22)` 加 `X +0.2、Z +0.2` 得 `(0.2,0.3,-0.02)`；东由 `(0.2,0.3,-0.22)` 加 `X +0.2、Z +0.2` 得 `(0.4,0.3,-0.02)`；西由 `(-0.2,0,-0.22)` 加 `X -0.2、Z +0.2` 得 `(-0.4,0,-0.02)`。原版角度为北/东/南 `273°` 不翻转，西 `87°` 翻转（当前 `equippedAngleOffset=220`）；使用单独南向图后，SYS 的南向 XML 角度填 `93°`。

SYS 扩展组件接管全部四向的非瞄准持握位置和角度：其 `case 0/1/2/3` 分别取北、东、南、西 `Offset`，其中南/西传 `isFlip=true`；绘制材质始终取 `eq.Graphic.MatSingle`。`Thing_DeathBow.Graphic` 只在装备者朝南且没有瞄准时返回 XML 的 `heldSouthTexPath` 单图，其余情况返回原图。新图接近原图的上下翻转；SYS 南向翻转网格交换左右 UV，两个方向的翻转合成 180°，因此南向配置 `93°` 与原图使用 `273°` 的朝向对应。瞄准分支继续使用原图及上一节的东西向偏移。SYS 绘制固定用 `plane10`，不读取 `drawSize=1.2`；当前实现保留 SYS 的这一尺寸行为。工作区 Release 编译与 XML 解析通过，尚未在游戏中验收新图。

## 机制口径

- 武器分类:带远程动词 → `IsRangedWeapon=true`,与狙击步枪同型(远程为主 + 保留近战 tool)、近战走原版 tool+机动。
- 射击完全走原版攻击命令:闪弓模式下射击动词使用原版参数(`isPrimary=true`、`hasStandardCommand=true`),装备按钮栏出现原版远程攻击命令(快捷键同样走原版绑定);普通模式或死之箭耗尽时,该动词被换成同实例的休眠参数(`isPrimary/hasStandardCommand/targetable` 全关),武器只剩近战动词与近战命令。参数切换只改这三个布尔,"弹丸/射程/瞄准时间"字段保持一致,且只在非预热、非爆发时执行。
- 精度:`statBases` 四段基础精度 64/74/84/74;每阶在武器统计上叠加 +4%/8%/12%/16%(写入 XML 的 `accuracyOffset`,可随时改)。
- 瞄准时间:四阶各自的总值 4 / 5.4 / 6.8 / 8.2 秒(基础 4 秒 + 该阶增量 0/1.4/2.8/4.2),由射击动词的 `WarmupTime` 提供。
- 弹丸:伤害 24/34/47/66(33.6、47.04 取整),穿透 0.34/0.476/0.6664/0.933,速度 44.4,抑止 4;伤害类型沿用原版 `Arrow`。
- 箭矢层数:命中血肉单位后挂 1 层,同一单位最多 4 层;每层 `IncomingDamageFactor +0.14`;不可自然愈合、不可包扎,一次手术清除全部层数(与豪猪棘刺同结构)。
- 意识增益:每次射击完成后给射手刷新 4 小时(10000 tick)的意识 +14%,重复射击只刷新不叠加。

## 蓄力阶切换特效(浮现印迹)

**结论**:蓄力阶切换完成时(与切换音效同一时点),在装备者身上挂一枚绑定角色的 Mote,表现"淡入 → 保持 → 上浮回落 → 淡出",约 1.18 秒后由原版机制自行销毁。连续切换不叠图:上一枚仍在播放且宿主未变时,只把它的时间轴推回起点重播。

**为什么走 Mote 而不是自绘**:装备中的武器不是地图上的已生成物(`Thing.Spawned=false`),`ThingComp.PostDraw` 不会被调用,所以不能像 Milira 的棋子浮标那样在武器组件里 `Graphics.DrawMesh`。Mote 是地图上的真实 Thing,由地图动态绘制,天然满足"跟随角色、超时自毁、不入存档"三个要求,且不需要任何 Harmony 补丁或每帧热路径。

**实现分层**:

- XML(`Defs/Misc/Mote_BowOfDeath.xml`):`ParentName="MoteBase"` + `<thingClass>MoteAttached</thingClass>`;`<mote>` 段给 `fadeInTime 0.08 / solidTime 0.6 / fadeOutTime 0.5`(三段之和即 Lifespan 1.18)、`attachedDrawOffset (0,0,0.6)`(画面上下方向的头顶偏移)、`archHeight 0.35 / archDuration 1.18`(显示期间的上浮弧线);`graphicData` 指向 `VFX/Bow_of_Death_Stage_Vfx`,`shaderType MoteGlow`,`drawSize 1.5`。
- C#(`CompEquippable_DeathBow.PlayStageSwitchVfx`):取 `EquippedPawn` → 已有存活印迹且宿主相同则 `ForceSpawnTick(当前 tick)` 重播,宿主已变则 `Destroy()` 旧实例,否则 `MoteMaker.MakeAttachedOverlay(pawn, DeathBowDefOf.BowOfDeath_StageVfx, Vector3.zero)` 新起一枚。
- 触发点:`RequestStageSwitch` 的立即切换分支与 `ApplyPendingIfReady` 的延迟完成分支各调用一次 `PlayStageSwitchVfx()`,因此 0 tick 与带等待时间两种配置都在"该阶生效的同一帧"出特效,与 `<switchSound>` 完全同步;近战/闪弓模式切换不出该特效。

**参数口径**:改观感只动 XML —— 时长改 `<mote>` 三段(同时把 `archDuration` 调到不超过新的三段和),大小改 `drawSize`,位置改 `attachedDrawOffset`,浮起幅度改 `archHeight`;`stageSwitchVfx` 是运行时字段,不写入存档(mote 本身 `isSaveable=false`),读档后自然为空,下次切换重新生成。

## 蓄力瞄准特效（三层叠加，1.6，2026-10-18）

**结论**：身体层由三股不规则暗红风带构成，弯曲、细纹与透明空隙沿同一噪声场输送。朝右瞄准时，从脚边右下方流向身体左上方；其余方向继续由原有 `Mote_DeathBowAimAlignedVfx` 按 `瞄准角 - 90°` 旋转整块画布与局部偏移。此次只修改 1.6 与 Unity 工程。

**现行目录**：以下 MOD 文件均以 `鼠鼠收尾人们目前已到245679协会/1.6/` 为根；C# 与本知识库均在 `1.6/Source/`。旧记录中的根级 `Source/Defs/AssetBundles` 路径需按这个位置查找。

| 层 | 绘制来源 | 画布与图层 |
| --- | --- | --- |
| 身体层 `BowOfDeath_AimVfx` | `Trk/BowOfDeathAimWind`；三股程序风带，不取样 PNG 或噪声贴图 | `(2.4,2.8)` 格，局部偏移 `(0,0,0)`，`MoteOverhead` |
| 弓头扩散层 `BowOfDeath_AimChargeVfx` | `Trk/BowOfDeathAimCharge`，固定弓头锚点的程序扩散流线 | `(4,4)` 格，局部偏移 `(-0.2,0,0)`，`Gas` |
| 流线层 `BowOfDeath_AimStreakVfx` | 原版 `MoteGlow` 绘制现有流光 PNG | `(4,2)` 格，C# 沿瞄准方向偏移，`VisEffects` |

**身体层定位**：`_SourceU=0.66`、`_SourceV=0.30`。源点相对宿主为 `(U-0.5,V-0.5)×drawSize+attachedDrawOffset`，朝右基准下即 `(0.384,-0.56)` 格。`_FlowAngle=45` 在画布中给出向左上方向，`_FlowLength=0.68`、`_FlowWidth=0.17` 控制范围。画布大小不同于横纵真实流动角度，修改画布比例时需要复核实际显示。

**身体层成形**：沿流向与横向构造坐标，时间反向移动取样位置，使弯曲与细纹一起向左上输送。三股风带采用不同相位、厚度和起始偏移；低频噪声打散卷绕间距，Gaussian 横截面形成柔和边缘。`_RibbonWidth` 控制单股厚度，`_StartFeather` 控制错开起点的渐入范围。起点的渐入量还受各股噪声影响，不存在统一的起始裁剪截面。尾部继续在流动行程的68%至100%之间平滑淡出。`_DeepColor/_FlameColor/_HotColor` 分别控制柔和暗缘、暗红风带和红色细丝。

**易错点**：单一沿流向裁剪条件会让整层在同一条截面出现；在这条截面后统一淡入，仍可能暴露整齐的开始边界。消除分界需要分别处理各股起点、噪声渐入和横向软边，不能只增加整个画布的边缘模糊。

**Sustainer 的两条硬性要求**(原版 `SoundDef.ConfigErrors` 会报错):`sustain=true`;`priorityMode` 不能是 `PrioritizeNewest`,故取 `PrioritizeNearest`(`maxSimultaneous=2` 也只对 sustainer 生效)。结束机制:`Sustainer.SustainerUpdate` 中 `MaintenanceType.PerTick` 若超过 1 tick 未被 `Maintain()` 就 `End()`,再过 `sustainFadeoutTime` 秒清理;`Stance_Warmup.StanceTick` 每 tick 只负责 `Maintain()`,所以"瞄准被打断/结束"时声音自然停止,不需要手写停音。

**"只播放一次"的实现依据**:`soundAiming` 只能走 Sustainer(原版没有"瞄准开始时播一次单发音"的字段),所以用两个 SubSoundDef 字段把它压成一次性:① `sustainLoop=false` —— `SampleSustainer.TryMakeAndPlay` 只在 `sustainLoop=true` 时给 AudioSource 置 `loop=true`,关掉后素材播完即止;② `sustainIntervalRange=9999~9999` —— `SubSustainer.StartSample` 用 `nextSampleStartTime = 样本结束时刻 + sustainIntervalRange` 排下一次取样,值远超最长蓄力(8.2 秒)即整个瞄准期不会再起第二个样本。素材时长 2.18 秒 < 最短蓄力 4 秒,所以不存在被提前掐断的情况;若以后出现短于素材的蓄力,结束时会按 `sustainFadeoutTime` 淡出。

**混音口径(素材实测)**:三份素材实测 RMS 拉弓 -24.1 dBFS、射击 -18.1 dBFS、切换 -34.1 dBFS(切换素材首 0.25 秒约 -28 dB,后段长衰减到 -90 dB)。播放增益 = `volumeRange.RandomInRange / 100`(`SubSoundDef.RandomizedVolume`),因此切换素材故意给了 95~105 来补偿其本身偏低的电平;三处 volumeRange 就是以后调平衡的唯一入口。瞄准音用 `tempoAffectedByGameSpeed` 让素材播放速度跟随游戏速度,`muteWhenPaused` 保证暂停时不响。

**未改动项**:武器 `soundInteract`(拾取/交互音)仍是原版 `Bow_Large`;近战/闪弓模式切换音 `modeSwitchSound` 仍是占位 `Interact_PlasmaSword`。两者都不在本轮需求内。

## 踩坑记录(首次进游戏报出的配置错误)

- `ThingDef` 的 defName **不能以数字结尾**:`ThingDef.ConfigErrors` 对末位 `char.IsNumber` 报 "ends with a numerical digit, which is not allowed on ThingDefs."。基类 `Def.ConfigErrors` 只校验字符集 `^[a-zA-Z0-9\-_]*$`、不含此限制,只查基类会漏判。现有实例:`BowOfDeath_Arrow_Stage1~4` 改成 `..._StageOne/Two/Three/Four`;服装 `si1`/`si2` 改成 `si_uniform`/`si_quiver`。
- 带 `comps` 的 `HediffDef` 必须把 `hediffClass` 写成 `HediffWithComps` 或其子类,否则报 "has comps but hediffClass is not HediffWithComps or subclass thereof"(默认 hediffClass 是 `Hediff`)。意识增益 Hediff 因此显式加了 `HediffWithComps`。
- 跨引用不能指向抽象 Def:`RecipeDef.recipeUsers` 里写 `AnimalThingBase` 会报 "Could not resolve cross-reference"(抽象 Def 不参与跨引用解析)。改回原版豪猪棘刺的做法:手术配方不写 `recipeUsers`,用 `Patches/BowOfDeath_RecipeUsers.xml` 把配方名追加到种族 Def 的 `recipes` 列表;实定义用 `[defName="Human"]`,抽象定义必须用 `[@Name="AnimalThingBase"]`。
- `Graphic_StackCount` 属于 `Graphic_Collection`:`Init` 用 `ContentFinder<Texture2D>.GetAllInFolder(req.path)` 把 `texPath` 当**文件夹**取贴图,按 `name.Split('_')[0]` 分组、`orderby name` 排序,因此该文件夹内不能混放其它物品的贴图(会被一并收进 `subGraphics`)。只放一张单图会报 `Collection cannot init: No textures found at path ...`。`Graphic_Multi` 直接继承 `Graphic`,按 `texPath + _north/_east/_south/_west` 读取方向图,不走集合文件夹机制。
- 死之箭已按堆叠实现:`Textures/Item/Bow_of_Death_Arrow/` 放 `Bow_of_Death_Arrow_a/_b/_c.png`,Def 使用 `Graphic_StackCount` + `texPath=Item/Bow_of_Death_Arrow`;`Graphic_StackCount.SubGraphicForStackCount` 在 3 张贴图时按 `count==1` / `count==stackLimit` / 其余取 a/b/c。投射物贴图与配方图标仍用 `Textures/Weapon/Bow_of_Death_Arrow.png`。
- 原版信息卡的远程条目(伤害/穿透/瞄准时间/射程/抑止/爆发)读的是 `ThingDef` 上那条**默认弹丸**与静态动词参数,不随运行时状态变化。精度四项例外:它走武器统计,组件 `GetStatOffset` 一改面板就跟着变。
- 信息卡组装顺序(`RimWorld/StatsReportUtility.cs` 的 `DrawStatsReport(Rect, Thing)`)是:先 `thing.def.SpecialDisplayStats(req)`,再 `StatsToDraw(thing)`(内含 `thing.SpecialDisplayStats()`)。所以**只靠武器实例类删不掉 Def 级条目**,只能追加;要替换必须补 `ThingDef.SpecialDisplayStats` 的 Harmony 后置补丁(`XIYUNTE.DeathBowStatPatches`),并限定 `req.Thing is Thing_DeathBow`,其他武器与其他 Def 浏览不受影响。
- 统计展开面板里"基础值 → 最终值"缺少来源行,是组件没有实现 `ThingComp.GetStatsExplanation`;补上后精度条目会显示"当前蓄力阶段: +16%"。
- 玩家据点地图上原版只允许"带 `orderedTakeGroup` 的物品"被拾取进背包(`PawnUtility.CanPickUp`:`!Map.IsPlayerHome` 才无条件允许,否则要求 `def.orderedTakeGroup.max > 0`)。自制弹药要能被捡起,需要自定义 `OrderedTakeGroupDef` 并挂到物品 Def 上;这与物品是否可搬运无关。
- 品质为大师级及以上时,"基础精度 + 蓄力阶加成"再乘品质系数会被 `Accuracy*` 的 `maxValue=1`(以及命中计算内的 clamp)截到 100%,高阶蓄力的精度收益在高品质武器上看不出来。要突破需要放宽该 StatDef 上限或改成对命中率乘算,会影响所有远程武器,需另行确认。
- 蓄力阶的介绍文字(`stages[].description`)、图标(`stages[].iconPath`)与按钮图标(`modeIconPath`)均为必填项,缺失由 `Properties_DeathBow.ConfigErrors` 在加载期报错;介绍文字是静态文本,改动弹丸数值时必须同步修改。
- 原版 `Graphic_StackCount` 在 3 张贴图时的取图规则是"`stackCount==1` 取 a、`stackCount==stackLimit` 取 c、其余取 b",即"单/中间量/满上限":c 只在**堆满一格**时出现(stackLimit=75 就要 75 支才触发,不是第 3 支触发);`SubGraphicForStackCount` 未标记 virtual,`MatSingle` 固定取最后一张。
- 原版没有"逐数量换图(1/2/3+)"的现成类:全部 `Graphic_*` 中与堆叠取图相关的只有 `Graphic_StackCount` 和食物专用的 `Graphic_MealVariants`,后者的每组 3 张处理与前者一致,并在超过 3 组时直接 `throw new NotImplementedException`。死之箭因此直接使用原版 `Graphic_StackCount`(纯 XML),不写自定义类。
- 堆叠物品的 UI 图标:`Widgets.GetIconFor` 的实例分支走 `thing.Graphic.MatAt(rot, thing)`,按当前 `stackCount` 取图,所以物品栏会显示"两支"贴图;给 Def 加 `uiIconPath` 指向单支贴图即可让物品栏、存储与交易界面统一显示 a(判定顺序 `Thing.UIIconOverride` → 样式图标 → `def.uiIconPath` → 实例 Graphic)。
- Hediff 在健康页的文字颜色来自 `Hediff.LabelColor`(默认返回 `HediffDef.defaultLabelColor`);意识提升因此设为四协会红 `(150,39,43)`(取自 `Textures/Clothing/si_uniform.png` 红色主色),死之箭 3 张堆叠贴图与弹道贴图的红色也映射到同一色值。
- 弹道贴图放大:投射物父级 `BaseBullet` 未定义 `drawSize`,在 4 个投射物 Def 的 `graphicData` 内加 `drawSize(2,2)` 即放大一倍,贴图文件本身保持 256x256。
